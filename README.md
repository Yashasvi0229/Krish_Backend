# GNC Invoice Automation — Backend

Python/FastAPI backend for GNC Group's insurance-claim invoice automation.
Frontend lives in a separate repo (React 18 + Vite).

**Stack:** Python 3.11 · FastAPI · SQLAlchemy 2 (async) · PostgreSQL · Redis · Celery · Alembic

---

## Roadmap

We build this in 4 steps. Only Step 1 is done — the rest are file skeletons
with docstrings explaining what will go there.

## Deploy to Render (first-time setup)

Render's free tier is enough to boot the whole stack. Follow in order:

### 1. Push this repo to GitHub

```bash
git init
git add .
git commit -m "Initial scaffold"
git remote add origin https://github.com/<you>/gnc-invoice-backend.git
git push -u origin main
```

### 2. Create the services in Render

1. Go to [dashboard.render.com](https://dashboard.render.com) → **New +** → **Blueprint**
2. Connect your GitHub account, pick this repo.
3. Render reads `render.yaml` and offers to create:
   - **PostgreSQL** — `gnc-invoice-db` (free)
   - **Key-Value / Redis** — `gnc-invoice-redis` (free)
   - **Web Service** — `gnc-invoice-backend` (free, Docker build)
4. Click **Apply**. First Docker build takes 5–8 minutes.

### 3. Fill in the secrets

`render.yaml` marks some env vars as `sync: false` — Render will not
auto-populate these. Set them in the web service's **Environment** tab:

| Env var                | Value                                                                                       |
|------------------------|---------------------------------------------------------------------------------------------|
| `FRONTEND_URL`         | Your frontend URL, e.g. `https://gnc-invoice-frontend.onrender.com`                         |
| `ALLOWED_ORIGINS`      | Same as `FRONTEND_URL`, comma-separated if multiple                                         |
| `KEY_ENCRYPTION_KEY`   | Generate: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` |
| `GOOGLE_CLIENT_ID`     | From Google Cloud Console (Step 3)                                                          |
| `GOOGLE_CLIENT_SECRET` | From Google Cloud Console                                                                   |
| `GOOGLE_REDIRECT_URI`  | `https://gnc-invoice-backend.onrender.com/api/auth/google/callback`                         |
| `CLAUDE_API_KEY`       | From console.anthropic.com (Step 5)                                                         |

`SECRET_KEY` is auto-generated by Render (see `generateValue: true` in `render.yaml`).
`DATABASE_URL`, `REDIS_URL`, `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND` are
auto-populated from the DB and Redis services.

### 4. Verify it's live

Render will auto-deploy after every git push. Once the first build is green:

```bash
curl https://gnc-invoice-backend.onrender.com/health
# → {"status":"ok","app":"GNC Invoice Automation","version":"1.0.0","env":"production"}

curl https://gnc-invoice-backend.onrender.com/health/ready
# → {"status":"ok","checks":{"database":"ok","redis":"ok"}}
```

`/docs` (Swagger UI) is disabled in production. Set `APP_ENV=development`
in Render to enable it temporarily.

### 5. Every subsequent deploy

Just `git push`. Render's `autoDeploy: true` picks it up automatically.
For manual deploys: dashboard → the service → **Manual Deploy** → **Deploy latest commit**.

## Roadmap (details)

### ✅ Step 2 — Database models (shipped)
13 SQLAlchemy 2.0 tables in `app/models/` covering the full spec §16.3:
`users`, `clients`, `claims`, `emails`, `attachments`, `ai_analyses`,
`billing_rules`, `processing_jobs`, `invoice_drafts`, `invoices`,
`billing_ledger`, `audit_logs`, plus a singleton `gmail_connection`
table for the shared GNC mailbox.

Initial migration lives at `alembic/versions/0001_initial_schema.py`
and is applied automatically by the Docker CMD on every container start:
`alembic upgrade head && uvicorn app.main:app ...`. Idempotent — a no-op
when the DB is already at head; a failed migration aborts the transaction
and prevents the app from starting rather than serving a broken schema.

Verify tables after deploy:
```bash
# From Render dashboard → gnc-invoice-db → "Connect" → External connection string
psql <external-url> -c "\dt"
```
You should see 14 rows (13 tables + `alembic_version`).

### Step 3 — Auth (next)
Simple email/password login using hardcoded admin credentials from env vars.
Also adds the Gmail connection flow: an admin runs a one-off OAuth handshake
against the shared GNC Gmail account, and the refresh token is stored
(Fernet-encrypted) in the singleton `gmail_connection` table. From then on,
all Gmail reads use that single shared credential.

Register a Google Cloud OAuth app with these scopes:
- `openid email profile`
- `https://www.googleapis.com/auth/gmail.readonly`

Authorized redirect URI: `https://gnc-invoice-backend.onrender.com/api/auth/google/callback`

### Steps 4–6
See docstrings in the corresponding files under `app/`.

## Project structure

```
gnc-invoice-backend/
├── app/
│   ├── main.py               ← FastAPI entry point
│   ├── config.py             ← env vars → Settings object
│   ├── database.py           ← async SQLAlchemy engine + get_db()
│   ├── celery_app.py         ← Celery instance
│   ├── api/                  ← HTTP routers (auth, invoices, drafts, …)
│   ├── models/               ← SQLAlchemy ORM classes (users, clients, …)
│   ├── schemas/              ← Pydantic request/response models
│   ├── repositories/         ← DB queries — one class per aggregate
│   ├── services/             ← Business logic
│   │   ├── ai/               ←   AI provider abstraction (Claude/OpenAI/Gemini)
│   │   └── billing/          ←   Rule engine + rate strategies + line splitter
│   ├── workers/              ← Celery task definitions
│   ├── core/                 ← logging, exceptions, middleware, security, RBAC
│   ├── utils/                ← hashing, file storage, date helpers, …
│   └── integrations/         ← Google OAuth, Gmail API, Pub/Sub
├── alembic/                  ← DB migrations
├── scripts/                  ← seed/admin one-off scripts
├── tests/                    ← unit / integration / e2e
├── Dockerfile                ← Render uses this
├── render.yaml               ← Render blueprint (all services)
├── requirements.txt
├── requirements-dev.txt
├── .env.example              ← template — copy to .env for local work
└── .gitignore
```

Every empty `.py` file has a docstring naming what it will contain and
which spec section covers it.
